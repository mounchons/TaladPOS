# คู่มือ Reset ข้อมูลทดสอบ

ล้างข้อมูลในระบบ แล้วสร้างชุดข้อมูลทดสอบชุดเดิมขึ้นมาใหม่ด้วยคำสั่งเดียว
ใช้ทุกครั้งที่ต้องการเริ่มทดสอบจากสถานะตั้งต้น เช่น ก่อนรอบทดสอบใหม่ หลังทดสอบขายจนสต็อกเปลี่ยน
หรือเมื่อข้อมูลเลอะจากการลองแก้/ลบ

**ผู้อ่าน**: QA และนักพัฒนาที่ต้องการข้อมูลตั้งต้นที่รู้ค่าแน่นอน
**ส่วนประกอบ**: `scripts/reset-test-data.ps1` (ตัวเรียก) → `api/tools/TaladPOS.TestData` (console app ที่ทำงานจริง)

ป้ายในคู่มือนี้ใช้แบบเดียวกับ [docs/qa](qa/README.md):
✅ **ผลจริง** = รันจริงแล้วคัดลอกผลมา · 🧮 **คำนวณจากกติกา** = ยังไม่ได้ลองกดจริง แต่คิดจากโค้ดส่วนลด

## 1. สรุปสั้น ๆ

```powershell
./scripts/reset-test-data.ps1
```

| ตาราง | หลัง reset |
|---|---|
| `products` | 20 รายการตาม [`docs/image/product/products.json`](image/product/products.json) พร้อมรูป |
| `promotions` | 8 รายการ ครบทุกสถานะ (ใช้งานอยู่ / หมดอายุ / ยังไม่เริ่ม) |
| `conditional_promotions` + `conditional_promotion_lines` | 3 รายการ ครบทั้งสามรูปแบบของฟีเจอร์ 003 (ดูตารางด้านล่าง) |
| `sale_applied_promotions` | สร้างตามบิลที่ได้สิทธิ์โปรโมชั่นแบบมีเงื่อนไข |
| `members` | 5 คน |
| `sales` + `sale_line_items` | บิลย้อนหลัง 45 วัน (วันละ 1–3 บิล) + บิลวันนี้ 4 บิล ≈ 96 บิล |
| `staff` | **ไม่ถูกล้าง** — login `manager` / `Manager123!` และ `cashier` / `Cashier123!` ใช้ต่อได้ |

### โปรโมชั่นแบบมีเงื่อนไขที่ถูกสร้าง

| ชื่อ | เงื่อนไข | สิ่งตอบแทน | ใช้ทดสอบ |
|---|---|---|---|
| ซื้อคู่แถมส้มโอ | มะม่วง 1 + แตงโม 1 | แถมส้มโอ 1 | US1 — ของแถมเป็นสินค้าคนละตัวกับเงื่อนไข |
| มะม่วงซื้อ 2 แถม 1 | มะม่วง 2 | แถมมะม่วง 1 | US2 — ของแถมเป็นสินค้าเดียวกับเงื่อนไข |
| ซื้อคู่ลด 15% | มะม่วง 1 + ทุเรียน 1 | ลด 15% | US3 — ส่วนลดเป็นเปอร์เซ็นต์ |

สองรายการแรกกับรายการที่สามแย่ง **มะม่วง** กันโดยตั้งใจ ชุดข้อมูลหลัง reset จึงมีกรณีโปรโมชั่นซ้อนทับกันเสมอ
ซึ่งเป็นกรณีที่กติกาการจัดลำดับใน FR-019 มีไว้เพื่อตัดสิน

ทำงานใน transaction เดียว ถ้าล้มกลางทาง ข้อมูลเดิมยังอยู่ครบ ไม่มีสภาพ "ล้างไปครึ่งเดียว"

## 3. วิธีรัน

### 3.1 Windows (แนะนำ)

จาก root ของ repo:

```powershell
./scripts/reset-test-data.ps1
```

script ทำ 3 ขั้น: `docker compose up -d postgres` → รอจน `pg_isready` ผ่าน (สูงสุด 30 วินาที) → รัน tool

| พารามิเตอร์ | ใช้เมื่อ |
|---|---|
| `-SkipDocker` | PostgreSQL ไม่ได้รันผ่าน docker compose ของโปรเจกต์นี้ (เช่น ติดตั้งเองในเครื่อง) |
| `-ImageBaseUrl http://<host>:<port>` | เปิดเว็บจาก origin อื่นที่ไม่ใช่ `http://localhost:3000` เช่น ทดสอบจากมือถือผ่าน IP เครื่อง |

### 3.2 macOS / Linux หรือเมื่อ PostgreSQL รันอยู่แล้ว

```bash
docker compose up -d postgres     # ถ้ายังไม่ได้เปิด
dotnet run --project api/tools/TaladPOS.TestData
```

ส่ง option ต่อท้ายหลัง `--`:

| Option | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--connection <string>` | env `ConnectionStrings__TaladPOSDb` → ค่า dev (`Host=localhost;Port=5432;Database=taladpos;...`) | connection string ของ PostgreSQL |
| `--products-json <path>` | `docs/image/product/products.json` | แคตตาล็อกสินค้า |
| `--image-base-url <url>` | `http://localhost:3000` | origin ที่ใช้สร้าง `ImageUrl` |
| `--repo-root <path>` | หาเองจากโฟลเดอร์ที่มี `api/TaladPOS.sln` | root ของ repo |
| `--allow-any-database` | ปิด | ยอมล้าง database ที่ไม่ได้ชื่อ `taladpos` |
| `--help` | – | แสดงวิธีใช้ |

ตัวอย่าง: `dotnet run --project api/tools/TaladPOS.TestData -- --image-base-url http://192.168.1.10:3000`

### 5.2 รูปสินค้า

- tool copy รูปทั้งสองขนาดจาก `docs/image/product/` ไปไว้ที่ `web/public/images/products/`
  (โฟลเดอร์นี้ถูก git ignore เพราะสร้างใหม่ได้ทุกครั้ง) และข้ามไฟล์ที่ copy ไว้แล้วและยังไม่เปลี่ยน
- `ImageUrl` ของสินค้าเก็บ **รูปเล็ก**: `http://localhost:3000/images/products/<slug>-512.png`
- **รูปใหญ่** วางคู่กันในโฟลเดอร์เดียว หาได้โดยเปลี่ยน `-512` เป็น `-1024` (schema มีฟิลด์รูปช่องเดียว จึงไม่ได้เก็บแยก)
- ใช้ URL เต็มแทน path สั้น เพราะช่อง "URL รูปภาพ" ในฟอร์มแก้ไขสินค้าเป็น `type="url"`
  ถ้าเก็บเป็น `/images/...` จะกดบันทึกฟอร์มไม่ผ่าน

ช่วงวันกำหนดแบบนับจาก **วันที่รัน reset** (ใช้วันตามเวลา UTC เหมือนที่ API ใช้ตัดสินว่าโปรใช้งานอยู่)

| Item | 25% | มะม่วง | สมาชิก | −5 ถึง +5 | ใช้งานอยู่ | สองโปรชนกัน ต้องได้ตัวที่ลดมากกว่า (FR-022) |
| Item | 15% | แตงโม | สมาชิก | −10 ถึง +14 | ใช้งานอยู่ | โปรเฉพาะสมาชิก |
| Item | 20% | ทุเรียน | ทุกคน | −45 ถึง −31 | หมดอายุ | ต้องไม่ถูกนำมาคิด |

### 5.5 บิลขาย

- ย้อนหลัง 45 วัน วันละ 1–3 บิล เวลาเปิดร้าน 08:00–20:00 (เวลาไทย) + บิลวันนี้ 4 บิล ซึ่งเวลาไม่เกินตอนที่รัน
- ขายโดย cashier ประมาณ 2 ใน 3 ที่เหลือเป็น manager · ประมาณ 40% ของบิลผูกกับสมาชิก
- บิลละ 1–4 สินค้า ชิ้นละ 1–3 หน่วย สินค้ายอดนิยม (มะม่วง กล้วยหอม ส้ม) ถูกสุ่มเจอบ่อยกว่า
- ส่วนลดของแต่ละบิลคิดด้วย `DiscountResolver` **ตามวันที่ของบิลนั้น** ด้วยวิธีเดียวกับ `CompleteSaleUseCase`
  (ส่วนลดรายสินค้าที่ดีที่สุด + ส่วนลดทั้งบิลที่ดีที่สุด แบ่งสัดส่วนลงแต่ละบรรทัด)

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `password authentication failed for user "taladpos"` | พอร์ต 5432 เป็นของ PostgreSQL ตัวอื่น (รหัสผ่านไม่ได้ผิด) | `docker ps` ดูว่าใครจับ 5432 อยู่ หยุดตัวนั้น แล้วรันใหม่ |
| `docker compose up failed` / `port is already allocated` | สาเหตุเดียวกับข้างบน | เหมือนข้างบน |
| `Reset failed: ...` ตามด้วย `Is PostgreSQL running?` | ต่อฐานข้อมูลไม่ได้ | `docker compose up -d postgres` หรือเช็ก `--connection` |
| `Refusing to reset database '...'` | database ไม่ได้ชื่อ `taladpos` — ตัวกันพลาดของ tool | ตรวจ connection string ถ้าตั้งใจจริงใส่ `--allow-any-database` |
| `Missing product images: ...` | ไม่มีไฟล์รูปตามที่ `products.json` อ้าง | `git pull` หรือวางรูปให้ครบ |

| รูปสินค้าในเว็บไม่ขึ้น | เว็บไม่ได้เปิดที่ `http://localhost:3000` หรือ `next dev` ยังไม่เห็นโฟลเดอร์ `web/public` ที่เพิ่งสร้าง | reset ใหม่ด้วย `-ImageBaseUrl` ให้ตรง origin จริง หรือ restart `npm run dev` |
| checkout error หลัง reset ขณะเปิดเว็บค้างไว้ | ตะกร้าเก่ายังถือ id สินค้าชุดก่อน reset | รีเฟรชหน้า/ล้างตะกร้าแล้วเลือกสินค้าใหม่ |
| build API ผ่าน แต่ API ไม่ขึ้น (ไม่มีอะไรฟังพอร์ต 5054) | `dotnet` ที่ถูกเรียกไม่มี runtime 8 เช่นเครื่องที่มี `~/.dotnet` ติดตั้งแค่ .NET 10 และหน้าต่าง terminal ใหม่ไปเจอตัวนั้นก่อน | ตรวจด้วย `dotnet --list-runtimes` แล้วเรียกด้วย path เต็ม เช่น `& 'C:\Program Files\dotnet\dotnet.exe' run --project src/TaladPOS.Api --launch-profile http` |

## 9. ใช้กับเทสต์อัตโนมัติ

Integration test ของ API (`TaladPOS.Api.IntegrationTests`) ใช้ database แยกชื่อ `taladpos_test` และล้างข้อมูลเอง
**ไม่เกี่ยวกับ tool นี้** และ tool ก็ไม่ยอมล้าง `taladpos_test` เว้นแต่ใส่ `--allow-any-database`

สำหรับ E2E บนเว็บ (Playwright — ยังไม่มีในโปรเจกต์ ดู [docs/qa บทที่ 2](qa/02-write-tests.md))
ให้เรียก tool ใน `globalSetup` เพื่อเริ่มทุกรอบจากข้อมูลชุดเดียวกัน:

```ts
// global-setup.ts
import { execSync } from "node:child_process";

export default function globalSetup() {
  execSync("dotnet run --project ../api/tools/TaladPOS.TestData", { stdio: "inherit" });
}
```

แล้วเขียนเทสต์ให้อ้างสินค้าด้วยชื่อหรือบาร์โค้ดจากหัวข้อ 5.1 ไม่ใช่ id
