# Quickstart: ตรวจรับฟีเจอร์ Export รายงานสต็อกคงเหลือและประวัติการขาย

คู่มือนี้เป็นขั้นตอน **ตรวจรับด้วยมือ** (ไม่มี automated test framework ใน `web/` ในปัจจุบัน — ดู
`plan.md` หัวข้อ Technical Context > Testing) ใช้ยืนยันว่าฟีเจอร์ทำงานตรงตาม `spec.md` แบบ end-to-end

## Prerequisites

- ตั้งค่าและรัน `api/` + `web/` ตามขั้นตอนใน `api/README.md` และ `web/README.md` (ต้องมี PostgreSQL รันอยู่)
- ติดตั้ง dependency ใหม่ก่อนรันรอบแรกหลัง implement: `cd web && npm install` (จะดึง `exceljs` ตามที่ระบุใน
  `research.md`)
- บัญชีทดสอบจาก `DevelopmentSeeder`: `manager` / `Manager123!` (role Manager) และ `cashier` / `Cashier123!`
  (role Cashier) — ดู `docs/logic/authorization-roles.md`

## 1. Export สต็อกคงเหลือ (US1)

1. ล็อกอินด้วยบัญชี `manager`
2. ไปที่หน้า "รายงาน" (`/reports`) สลับไปแท็บ "สต็อกคงเหลือ"
3. จดจำนวนแถวและค่าที่แสดงบนตาราง (ชื่อสินค้า/จำนวนคงเหลือ/สถานะ) ไว้เทียบ
4. กดปุ่ม export
5. **คาดหวัง**: ได้ไฟล์ `taladpos-stock-report-*.xlsx` ดาวน์โหลดลงเครื่องภายในไม่กี่วินาที (SC-001, SC-004)
6. เปิดไฟล์ด้วยโปรแกรม spreadsheet (Excel, LibreOffice Calc, Google Sheets ก็ได้)
7. **คาดหวัง**: จำนวนแถวและค่าตรงกับที่จดไว้ในข้อ 3 ทุกแถว หัวคอลัมน์เป็นตัวหนา อ่านภาษาไทยได้ถูกต้อง ไม่มี
   ตัวอักษรเพี้ยน (SC-002 ส่วนที่เกี่ยวกับความครบถ้วน, SC-003)

**เคสตารางว่าง**: ถ้าร้านทดสอบไม่มีสินค้าเลย กดปุ่ม export ต้องยังได้ไฟล์ (มีแค่หัวคอลัมน์ 3 คอลัมน์) ไม่ใช่
ข้อความ error (FR-011)

**เคสสิทธิ์**: ล็อกเอาต์แล้วล็อกอินใหม่ด้วยบัญชี `cashier` → ต้องเข้าหน้า "รายงาน" ไม่ได้เลยตั้งแต่แรก
(เจอ "หน้านี้เปิดให้เฉพาะผู้จัดการ") จึงไม่มีทางเห็นปุ่ม export ของรายงานนี้ (SC-005)

## 2. Export ประวัติการขาย (US2)

1. ล็อกอินด้วยบัญชี `manager` หรือ `cashier` ก็ได้ (ทั้งสอง role ต้องใช้ได้)
2. ทำรายการขายให้ได้บิลมากกว่า 20 บิลในช่วงวันที่เดียวกัน (มากกว่า 1 หน้าจอของตาราง — ทำผ่านหน้าขายสินค้า
   ซ้ำหลายรอบ หรือ seed ข้อมูลเพิ่มถ้ามี script อยู่แล้ว)
3. ไปที่หน้า "ประวัติการขาย" (`/sales/history`) ตั้งช่วงวันที่ให้ครอบคลุมบิลทั้งหมดที่เพิ่งทำในข้อ 2
4. จดจำนวนบิลทั้งหมดที่ตรงกับตัวกรอง (ดูจาก pager ด้านล่างตาราง เช่น "ทั้งหมด 45 รายการ")
5. กดปุ่ม export
6. **คาดหวัง**: ไฟล์ที่ได้มีจำนวนแถวเท่ากับจำนวนที่จดไว้ในข้อ 4 **ทั้งหมด** ไม่ใช่แค่ 20 แถวของหน้าแรก
   (SC-002 — ข้อยืนยันหลักของฟีเจอร์นี้)

**เคสตัวกรอง**: ติ๊ก "เฉพาะบิลของฉัน" แล้ว export ซ้ำ → ไฟล์ต้องมีเฉพาะบิลที่พนักงานที่ล็อกอินอยู่เป็นผู้ขาย
เท่านั้น เทียบจำนวนกับ pager หลังติ๊กตัวกรอง

**เคสเกินเพดาน** (ทำได้ถ้ามีข้อมูลทดสอบมากพอ หรือปรับ `SALES_EXPORT_ROW_CAP` ในโค้ดลงชั่วคราวเพื่อทดสอบ):
ตั้งตัวกรองให้จับคู่กับบิลเกิน 10,000 รายการ (หรือเกินค่าที่ปรับไว้ทดสอบ) แล้วกด export → **คาดหวัง**: ระบบ
**ไม่** ดาวน์โหลดไฟล์บางส่วน แต่แสดงข้อความแจ้งให้แคบช่วงวันที่/ตัวกรองลง (FR-006, edge case ของ spec)

**เคสจับเวลาใกล้เพดาน (SC-004)**: ปรับ `SALES_EXPORT_ROW_CAP` ในโค้ดลงชั่วคราวเป็นค่าที่ทดสอบได้จริง (เช่น
500) เตรียมข้อมูลให้ใกล้ค่านั้น (เช่น 490 บิล) แล้วจับเวลาจริงตั้งแต่กดปุ่ม export จนไฟล์พร้อมดาวน์โหลด (ใช้
นาฬิกาจับเวลา หรือแท็บ Network ของ browser devtools) → **คาดหวัง**: ไม่เกิน 5 วินาที (SC-004) — เคสนี้สำคัญ
กว่าการจับเวลากับข้อมูลน้อย ๆ เพราะเป็นจุดที่เสี่ยงเกิน 5 วินาทีที่สุด

**เคสตารางว่าง**: ตั้งตัวกรองให้ไม่มีบิลตรงเลย (เช่นช่วงวันที่ในอนาคต) แล้ว export → ต้องยังได้ไฟล์ที่มีแค่
หัวคอลัมน์ 6 คอลัมน์ ไม่ error (FR-011)

## 3. เคสร่วม — กันกดซ้ำระหว่างเตรียมไฟล์

จากทั้งสองหน้า: กดปุ่ม export แล้วรีบกดซ้ำทันทีก่อนไฟล์จะพร้อม → **คาดหวัง**: ปุ่มแสดงสถานะกำลังโหลดและกด
ซ้ำไม่ได้จนกว่าไฟล์แรกจะเสร็จ (ดาวน์โหลดหรือ error) ไม่มีการสร้างไฟล์ซ้ำสองใบ ไม่มีอาการหน้าจอค้าง (FR-008)
